1. Executive Architecture & System Overview

Rakt-Connect is an enterprise-grade digital public healthcare infrastructure engineered to resolve critical inefficiencies in India's blood banking ecosystem. The architecture balances data immutability with high-performance predictive intelligence:

Core Architectural Axiom
Blockchain = Immutable Memory: Hyperledger Fabric provides honest, tamper-evident audit trails, regulatory multi-party consensus, and non-repudiable legal proofs.
AI Microservice = Predictive Brain: Temporal Fusion Transformers (TFT) and spatial algorithms forecast regional blood shortages, optimize shelf-life decay (FIFO), and direct emergency dispatches.

The system operates across three tiers:

  • Tier 1: Client & Presentation Layer — Next.js 14 Web Command Center (12 specialized management consoles) and Flutter Donor Mobile App (8 screens with DID & QR scanning).
  • Tier 2: API Gateway & Security Interoperability Layer — Node.js/Express gateway integrating national ABDM health identifiers, NHCX insurance routers, and Post-Quantum cryptographic vaults.
  • Tier 3: Distributed Ledger & AI Compute Layer — Hyperledger Fabric v3.0 (Raft consensus, CouchDB state database, 3 Orgs) coupled with a Python FastAPI AI engine.
What is ABDM? Ayushman Bharat Digital Mission — India's national initiative to develop an integrated digital health infrastructure.
What is ABHA? Ayushman Bharat Health Account — A unique 14-digit identifier establishing a verified digital health identity for citizens.
What is NHCX? National Health Claims Exchange — A unified gateway for standardizing and auto-adjudicating health insurance claims across payers and providers.
What is DPDP Act 2023? Digital Personal Data Protection Act 2023 — India's statutory data protection law mandating explicit consent, purpose limitation, and strict privacy controls.

Volatile Cache (TTL 30m): An in-memory temporary session store that expires automatically after 30 minutes, preventing repeated heavy network requests to the government gateway.

Algorithm 3: Post-Quantum Cryptographic Ledger Vault Encrypter

NIST FIPS 203 ML-KEM (Kyber-768) AES-256-GCM

1. Conceptual Background: "What Means What"

Post-Quantum Cryptography (PQC): Cryptographic algorithms designed to withstand attacks by both classical and quantum computers (which can break RSA and ECC via Shor's algorithm).
Kyber-768 (ML-KEM): NIST-standardized Module Lattice-Based Key Encapsulation Mechanism. It uses public keys of 1184 bytes to establish shared secrets securely.
HKDF-SHA256: HMAC-based Key Derivation Function that expands a raw shared secret vector into a cryptographic 256-bit symmetric key.
AES-256-GCM + IV + AAD: Advanced Encryption Standard in Galois/Counter Mode providing authenticated encryption. Uses a 12-byte Initialization Vector (IV) and Additional Authenticated Data (AAD) to prevent tampering.
Zero-Fill Memory Wipe: Explicitly overwriting memory buffers with zeros after encryption to prevent cold-boot memory recovery attacks.

2. How the Algorithm Works (Step-by-Step)

  1. Key Vector Bounds Check: Inspects the recipient's Kyber public key buffer. Must measure exactly $1184\text{ bytes}$.
  2. KEM Encapsulation: Executes lattice-based matrix multiplication to encapsulate a random shared secret vector $K$.
  3. Key Expansion: Expands secret $K$ with domain salt "RaktConnect_PQC_System_Salt_Verification_V1" via HKDF-SHA256 into a 32-byte key.
  4. Authenticated Encryption: Encrypts the plaintext blood record using AES-256-GCM.
  5. Memory Sanitation: Calls SecureMemoryWipeAndZeroFill() on all intermediate plaintext buffers.

k-Ring Hexagonal Expansion: Concentric rings of neighboring hexagons around a hospital. The formula for the total number of cells in a $k$-ring is $N(k) = 1 + 3k(k+1)$.
NBTC 90-Day Deferral Rule: National Blood Transfusion Council statutory rule mandating a minimum 90-day biological recovery gap between whole blood donations.

Circuit Breaker 3000ms Timeout Fail-Soft Insurance

3000ms Timeout Ceiling: If the national insurance server does not respond within 3 seconds, the request times out so that patient transfusion is never delayed.
Fail-Soft Architecture: A system resilience design where if a component fails, the system continues to operate in a safe degraded state instead of crashing or blocking.
DEFERRED_DISASTER_HOLD Voucher: A digital promissory asset minted on the local blockchain ledger guaranteeing government/insurance claim settlement post-emergency.

2. How the Algorithm Works (Step-by-Step)

6. Comprehensive Teacher Q&A & Viva Defense Guide

Q1: Why did you choose Hyperledger Fabric instead of Ethereum, Solana, or Polygon?

Answer: Healthcare records contain sensitive PII/PHI protected by India's DPDP Act 2023. Public blockchains (Ethereum/Polygon) have transparent ledgers and variable transaction gas fees. Hyperledger Fabric is a permissioned enterprise blockchain with Membership Service Providers (MSP), zero gas fees, deterministic Raft consensus, and private data collections, which matches national sovereign infrastructure requirements.

Q2: How does the system ensure patient privacy if the blockchain ledger is immutable?

Answer: We implement an off-chain storage and cryptographic hashing architecture. Plaintext health data is encrypted using Post-Quantum Kyber-768/AES-256-GCM and stored in secure off-chain vaults. Only one-way SHA-256 digests and §65B digital certificate proofs are committed on-chain. Thus, no medical records or PII are exposed on the ledger.

Q3: What makes your Disaster Mode (Algorithms 5 & 6) novel?

Answer: In natural calamities (floods, earthquakes), internet lines to central government servers (ABDM/NHCX) often fail. Our system uses a multi-signature quorum (k ≥ 3) to cryptographically activate Disaster Mode. This unlocks an offline fail-soft state where blood is issued under DEFERRED_DISASTER_HOLD vouchers. Once connectivity returns, Algorithm 7 executes atomic batch reconciliation to ensure zero record loss.

Q4: What is the significance of Section 80G tokenization in Algorithm 8?

Answer: Blood donation in India suffers from donor drop-offs. By linking the successful transfusion of blood directly to automated, fraud-proof Section 80G tax benefit tokens via smart contracts, we provide a legitimate, statutory incentive for repeat voluntary donations without financial commodification.

Q5: How can a teacher test and run these algorithms during the practical evaluation?

Answer: The project includes a dedicated Node.js verification harness. Run:

node demo_algorithms.js --all
This executes all 8 algorithms sequentially, printing inputs, constraints, execution logs, and output verifications. Individual algorithms can also be tested interactively using options 1 through 8.
